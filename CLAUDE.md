# Project: CaliCare — eczema & skin-condition care app for parents

## What this is
A native iOS app that helps parents of kids with eczema/TSW follow their
care plan and track progress with as little effort as possible.

## Product principles (never violate)
- Parents should rarely need to open the app. Prefer widgets, notification
  actions, App Intents (Siri, Action Button, Control Center) over in-app UI.
- Every log is one tap. Works offline, at night, one-handed.
- The app never recommends treatments. It organizes the plan the family's
  provider gave them. No medical claims. No diagnosis.
- No streaks, no guilt, no red for "bad." Severity uses lightness of sage green.
- Children's photos never leave the device.
- Beautiful and calm: warm cream background, generous spacing.

## Tech
- Bundle ID: com.cursorkittens.calicare (widgets: .widgets, Core: .core).
  Developer: CursorKittens LLC. Team ID: F2J8ZU2NQJ.
- SwiftUI, iOS 18+, Swift 6 concurrency, no third-party UI libraries.
- Xcode project is generated by XcodeGen from project.yml. Never edit
  .xcodeproj by hand; edit project.yml and run `xcodegen generate`.
- Targets: App, WidgetsExtension, Core (shared framework).
- Shared data lives in an App Group container so widgets and intents
  can read/write it: group.com.cursorkittens.calicare
- Local-first: SwiftData in the App Group. Sync to Supabase comes later
  (Phase 2); every model has id (UUID), createdAt, updatedAt, deletedAt,
  and a needsSync flag from day one.
- Secrets (API keys) never go in the app. AI calls go through Supabase
  Edge Functions.

## Design tokens
- Background #F8F3EA, card #FFFFFF, ink #2B2622, muted #6B6259
- Accent sage #4F6F57, sage dark #3F5E47, clay #8A5A3C, sand #F0E6D6
- Severity scale: #C9D6C9 (low), #8FA995 (medium), #3F5E47 (high)
- Fonts: Fraunces (headings), DM Sans (body), bundled (open-license).
- Night mode (8 PM – 7 AM): warm dark background #1E1B18, dimmed text.
- Cards 18pt radius. Touch targets at least 44pt. Dynamic Type and VoiceOver.

## Copy rules
- Plain, warm, short. "Worth watching," never "cause."
- No shaming language, no streaks, no "you missed."
- Shared reports include "Not medical advice."

## Workflow
- After every change, build with:
  xcodebuild -scheme App -destination 'platform=iOS Simulator,name=iPhone 16' build
  Fix all errors and warnings before saying you're done.
- Write unit tests for Core logic (models, scheduling, stats).
- Keep files small and focused.
- Tell me any manual step I must do in Xcode or on my device.
