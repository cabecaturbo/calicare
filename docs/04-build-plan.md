# Build Plan

## Stack
- **iOS app:** SwiftUI, iOS 18+, Swift 6. Built with Xcode; project generated by XcodeGen from project.yml.
- **Local-first data:** SwiftData stored in an App Group so the app, widgets, intents, and extensions share one database. Every log saves on the phone first, then syncs.
- **Supabase:** Sign in with Apple, Postgres with row-level security, background sync, Edge Functions for AI calls (Claude API key never in the app).
- **Vercel:** landing page, privacy policy (required by App Store), shared report web links later.
- **GitHub:** one commit per completed prompt.
- **Later:** StoreKit 2 (or RevenueCat) for subscriptions.

## Targets (grow over time)
App · Core (shared framework) · WidgetsExtension · Watch app · Messages extension · Keyboard extension

## Setup (manual, once)
1. Mac with latest Xcode.
2. Apple Developer Program ($99/yr).
3. `brew install xcodegen`
4. Empty GitHub repo, cloned; Claude Code opened in it.
5. CLAUDE.md saved in the repo root.

## How we write Claude Code prompts
- One focused goal per prompt.
- Numbered requirements.
- A "Done when" line that includes a successful build (and tests where logic is involved).
- Ask it to list any manual steps (signing, capabilities, device testing).
- Use plan mode (Shift+Tab), review, approve, build, commit, then `/clear` before the next prompt.
- Get one prompt at a time; report back results before the next.

## Phases
1. **One-tap logging** (no accounts): scaffold, data model, App Intents (Siri, Action Button, Control Center), interactive widgets, notification buttons, onboarding and Today screen.
2. **Sync and caregivers:** Supabase schema + RLS, Sign in with Apple, background sync of the local store, invite partner/caregivers, "logged by" names.
3. **Report cards:** render cards as images (ImageRenderer), share sheet, email, doctor PDF, iMessage extension, scheduled sends via Shortcuts, caregiver card.
4. **Care plans:** PDF/photo import (Edge Function → Claude → structured JSON → parent confirms), routine and topical checklists, bath rotation, patch-test timer, supplement ramp-up scheduler, "worse since when?" timeline, provider message/follow-up tracker, journal export.
5. **Food:** safe/testing/paused list, rotation planner by food family, plant counter, "what can I make" (AI, with code-level check against paused foods), leftovers/freezer timers, food trials, nutrient coverage.
6. **Photos, products, home:** on-device photo timeline with ghost overlay, product diary, restock reminders with affiliate links, home checklist, prescription/prior-auth/copay reminders, insurance history report.
7. **Launch:** Apple Watch app, keyboard extension, premium paywall, monthly recap, Vercel landing page + privacy policy, TestFlight beta with eczema parent groups, App Store submission.

## Phase 1 prompts

### Prompt 1: Project scaffold
```
Set up the project scaffold described in CLAUDE.md.
1. Create project.yml for XcodeGen with three targets: App (iOS app),
   WidgetsExtension (widget extension), and Core (framework shared by both).
2. Configure the App Group entitlement on App and WidgetsExtension.
3. Bundle Fraunces and DM Sans fonts (OFL licensed) and register them.
4. Create DesignSystem.swift in Core with colors, fonts, spacing, and radii
   from CLAUDE.md, including a night palette.
5. App shows a placeholder Today screen using the design system.
6. Run xcodegen generate and build for the simulator until it succeeds.
7. Add a .gitignore for Xcode projects.
Done when: the project builds cleanly and runs in the simulator. List any
steps I must do myself (like selecting my Apple Developer team).
```

### Prompt 2: Data model and local storage
```
Build the local data layer in Core using SwiftData, stored in the App Group
container so the app, widgets, and intents share one database.
Models:
- Child: name, birthDate (optional), colorTag, isActive.
- LogEvent: child, type, value (optional), note (optional), timestamp,
  loggedBy. Types: nightRating (good/okay/rough), itchEpisode, flare,
  bowelMovement (good/hard/loose/none), mood (great/okay/cranky),
  routineDone, note.
- Every model: id, createdAt, updatedAt, deletedAt, needsSync.
Also:
- LogStore with async functions: log(type:value:child:), undoLast(),
  events(for:child:day:), todaySummary(child:).
- "Current child" setting in shared UserDefaults (App Group).
- Unit tests for logging, undo, soft delete, day summaries.
Done when: tests pass and the build succeeds.
```

As built (the prompt actually run was more specific than the one above):
- LogEvent also has `entrySource` (widget, intent, notification, app, watch), and
  `log` takes `source:`.
- A care day runs 7 PM to 7 PM in the device time zone, so a night belongs to the
  morning it ends. From 7 PM on, "today" means tonight plus tomorrow.
- Uses a VersionedSchema (`SchemaV1`) plus a migration plan from day one.

### Prompt 3: App Intents
```
Create App Intents in Core so logging works without opening the app.
1. LogEventIntent: event type, optional value, optional child (defaults to
   current child). Writes through LogStore, returns a short confirmation
   like "Logged itchy wake-up for Cal, 2:14 AM." Must NOT open the app.
2. AppShortcutsProvider with Siri phrases: "Log a rough night in [APP NAME]",
   "Log itching in [APP NAME]", "Log a bowel movement in [APP NAME]".
3. A Control Center control (ControlWidget) that logs an itch episode.
4. Make the itch intent available to the Action Button via Shortcuts.
5. UndoLastIntent to reverse a mistaken tap from anywhere.
Done when: the build succeeds and you explain how to test each one.
```

### Prompt 4: Interactive widgets
```
Build interactive widgets in WidgetsExtension using the App Intents.
Tapping logs instantly; no app launch.
1. Small widget: one big "Itchy" button plus last-logged time.
2. Medium widget: Itchy, Rough night, Bowel movement, Routine done, with
   today's count for each.
3. Lock Screen widgets (circular, rectangular): itch log, last-night rating.
4. Configurable per child.
5. After a tap, briefly show "Logged" with an Undo button.
6. Night palette automatically from 8 PM to 7 AM.
Done when: widgets build, render in the widget gallery, and logs appear in
the database (add a debug list in the app to confirm).
```

### Prompt 5: Notification buttons
```
Add actionable notifications so parents log without opening the app.
1. Morning check-in (default 7:00 AM): "How was last night?" with actions
   Good / Okay / Rough that log a nightRating in the background.
2. Routine reminders (default 7:30 AM and 7:00 PM): actions Done / Snooze 30 min.
3. Actions write through LogStore without launching the app.
4. Settings screen for times and on/off toggles.
5. Ask for notification permission at a sensible moment with a friendly
   explanation, not at first launch.
Done when: each notification can be triggered in the simulator and its
actions log correctly.
```

### Prompt 6: Onboarding and Today screen
```
Build a minimal, beautiful in-app experience.
1. Onboarding (3 screens, no account): welcome, add child, set up widget and
   Action Button / Siri phrase.
2. Today screen: child's name, a calm one-sentence summary of last night,
   large one-tap log buttons, today's timeline (tap to edit or delete).
3. 7-day strip: nights as dots, daily skin level on the sage scale. No red.
4. Child switcher for multiple children.
5. Night palette automatically 8 PM – 7 AM.
6. VoiceOver labels, 44pt touch targets, Dynamic Type.
Done when: a new user goes from install to first widget log in under a
minute, and the build succeeds.
```

As built:
- Onboarding shows until finished once; quitting after adding a child resumes at
  quick-logging setup. The debug sample child is gone (onboarding adds the child).
- "Last night" follows the widgets: in the daytime it's the night that ended this
  morning; in the evening it switches to "Tonight so far" once tonight has a log.
- 7-day strip: night dot = the rating if given, else itchy wake-ups (1 / 2–3 / 4+).
  Skin square = itches + 3 per flare (0–2 / 3–5 / 6+). No logs = empty outline.
- In-app "Routine done" guesses morning before 2 PM, evening after.
- Edit changes time, kind, and note; delete is a soft delete. Both mark needsSync.
- Quick-logging steps are also in Settings; Recent logs stays at the bottom of Settings.

After Phase 1: use it with our own family for a few days, note what felt good or annoying, then write Phase 2 prompts around what was actually built.
